# Verify the data and training handoff

## Done predicate

The local handoff passes when every prepared row and referenced asset passes the declared schema, identity, split, label-evidence, licensing, and native Qwen processor checks, and extracted archives execute with their installed consumers. Real and generated sources remain distinguishable. The shared native tiny path must exercise training, exact resume, prediction, and fresh-process reload. The real checkpoint's tensor structure is checked separately. Pretrained inference, real-weight backward execution, and CUDA fit remain NOT_VERIFIED if the local host refuses memory admission. The automated Pod preflight must prove those paths before training proceeds.

The handoff must include executable commands, pinned dependencies, transfer checksums, machine-readable verification results, and this decision trail. No paid Pod, external teacher API, public upload, or larger GPU is authorized. CUDA memory and backend checks remain explicitly unverified until the RTX 4090 is connected. A GPU preflight must run before the paid training attempt.

Installed-consumer provenance compares canonical filesystem paths on both sides. macOS aliases such as `/var` and `/private/var` must not falsely reject the installed wheel. The consumer must still import from the isolated installation rather than the original editable checkout.

## Scope and current evidence

All six builders have executed. Assembly produced 44,904 questions, 3,503 unique images, and 750 videos. Real-photo acquisition produced 503 photographs.

The composition is 5,270 BANKING77-derived questions, 3,000 Open Images questions, 3,730 generated local text questions, 8,804 hard-v1 generated-rule questions, 6,100 rule-variants-v1 counterfactual questions, 15,000 generated visual questions, and 3,000 generated video questions. The generated share is 36,634 of 44,904. The published hard-v1 test partition and the 600-question held-out rule-structure set remain external. This controlled experiment does not establish generalist real-world performance.

Independent audits found and drove repairs for duplicate media, candidate/rubric shortcuts, visible-policy binding, source/holdout declarations, temporal observability, and runtime recovery. Current qualification is determined by current-hash machine-readable receipts. Human review and independent photo-visible truth remain unperformed.

## Named data shapes

`DecisionRecord` is the existing canonical JSONL record. Its evidence, question, and candidates are model-visible. Labels, provenance, audit facts, filenames, and split names are not model-visible.

`DecisionInput` contains visible state, instructions, ordered candidates, and media. `PreparedBatch` contains native tensors, ordered output keys, candidate endpoint positions, the decision position, masks, IDs, and expanded lengths. Supervision remains in `TrainingExample`, outside native arguments. One compiler owns image/video expansion.

`VerificationResult` records a check name, evidence artifact, and one of VERIFIED, NOT_VERIFIED, or INCONCLUSIVE. INCONCLUSIVE never counts as a pass.

`TrainingState` records the warmup or joint phase, optimizer and scheduler state, RNG states, data order and position, processed examples, and elapsed spending allowance. A checkpoint must recover the same next update.

## Throughput checkpoint

- Blocking first steps. Freeze ownership and contracts, acquire sources, assemble data, and ground the native training design before implementation.
- Independent workstreams. Data-source and label audits can proceed independently of training architecture exploration. Each worker owns a separate output file. Native preprocessing and packaging remain with the integration owner.
- Shared mutable state. Only the integration owner writes assembled splits, manifests, processor contracts, archives, and shared dependency configuration. Workers do not edit a module after handing it off. No data builder runs concurrently with an edit to its source.
- Smallest safe decomposition. Use two grounded exploration slices, two training-design candidates, one selected implementation owner, and an independent verification review. Do not build two trainers or ask workers to repeat deterministic whole-corpus checks by hand.

## Workflow

1. Ground data and training paths. Trace entrypoints, evidence boundaries, current limitations, and the native Qwen integration requirements.
2. Compare two complete training-handoff designs. Prefer fewer interfaces, native multimodal compatibility, reproducible artifact recovery, and a bounded single-GPU execution path.
3. Complete acquisition and assembly. Validate all rows, decode every asset, and reject source-group or exact-evidence leakage across partitions.
4. Run independent label and methodology audits. Recompute labels from underlying evidence where possible. Report inherited human-label uncertainty separately from rule correctness. Inspect actual rendered images and sampled clip frames.
5. Run the native processor over every prepared question. Confirm marker positions, complete candidate preservation, media metadata, and the 2,048-position admission limit. Do not truncate an over-budget example to make a check pass.
6. Implement the selected training design. Run the actual model path locally, then exercise an update, checkpoint resume, prediction, and fresh-process artifact reload. Record any platform limitation.
7. Package verified data and code. Keep final-test data separate. Retain source attribution and license text. Validate the extracted archives with their real consumers.
8. Run an independent final review. Record unresolved CUDA-only checks and scientific limitations. Do not label this corpus a validated generalist training recipe.

## Scientific checks

Report real-source results separately from generated-source results. Keep real-only and mixed training recipes distinguishable. A real-only baseline and a mixed-data experiment must use the same independent real evaluation set. Do not choose a synthetic-data percentage from precedent alone.

Image-blanking, wrong-image, changed-policy, video-order, option-order, and candidate-count controls test different claims. A generated-layout holdout is not a new real-world domain. Calibration on generated cases does not establish calibration on photographs or customer messages.

## Principles applied

Prove It Works requires execution against the real files and model rather than agent completion reports. Build the Lever makes verification rerunnable. Model the Domain gives evidence, model inputs, verification results, and resumable training state separate structures. Separate Before Serializing Shared State gives workers distinct outputs and leaves shared integration files with one writer. Foundational Thinking puts contracts and verification before trainer code. Sequence Work into Verifiable Units requires a passing check at each integration boundary. Laziness Protocol keeps one selected training implementation. Never Block on the Human permits local reversible checks without a permission loop.

Attack the Premise replaced repeated Tesseract tuning with exact renderer-specific pixel recognition after a whole-corpus failure census. Fix Root Causes repaired candidate/rule construction and observable media instead of relabeling failures. Make Operations Idempotent added completed-pilot receipt reconciliation. Boundary Discipline keeps strict JSON conversion and process supervision at external boundaries. Test Behavior, Not Implementation requires actual pixel/video, optimizer, reload, and crash-state outcomes. Explain the Number separates shortcut controls, fixture learning, memory admission, and unmeasured GPU quality.
